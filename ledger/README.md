# 事实台账（Fact Ledger）

> 借自 claire 出海「三 Skill」流程（2026-09-17，原文对照见知识库 `AI/实践/SZGuide.md`「外部对照」一节）。
>
> 这个站唯一的资产是「每句话都能担保」。台账把这句话从一条原则，变成一样可以逐行检查的东西。
>
> 这个目录不在 `content/guides` 里，网站构建时不会读取，不会变成网页。

## 规则

1. **正文里每一个具体事实**（站名、线路、时间、价格、政策、日期、数量）都要能在这篇文章的台账里找到对应的一行。
2. 只有状态为 ✅ / 👤 / ⚠️ 的行可以写进正文。⚠️ 要用保守措辞（about、roughly、check before you go）。
3. ❓ 证据不足的，**不写**。宁可少一句。
4. ❌ 查过是错的，**留在台账里，不删**。它记录的是「这个说法还会再冒出来」，下次有人（包括 AI）再提，直接对得上。
5. 每行带**核实日期**。站名、营业时间、票价、政策这类会过期的，在「复核」列写清楚多久复查一次。

## 状态

| 标记 | 含义 | 需要什么 |
|---|---|---|
| ✅ 一手核实 | 官方、运营方、政府来源 | 链接 + 核实日期 |
| 👤 第一手经验 | 木安本人的经历，经他确认 | 确认日期；正文可以用第一人称 |
| ⚠️ 二手来源 | 只找到媒体、本地资讯站、维基百科 | 链接；正文措辞要保守 |
| ❓ 证据不足 | 没有来源，或者来源互相矛盾 | 不许写进正文 |
| ❌ 已否决 | 查过是错的 | 写清楚错在哪、对的是什么 |

## 什么时候建台账

- **新写（CREATE）**：写之前先建台账，写作只引用台账里的说法。
- **更新旧文（REFRESH）**：动到哪一篇，就给哪一篇补台账。
- **不做**：不为十几篇旧文集中补台账。没有截止日期的补课，最后会变成又一个做不完的项目。

## 外部 AI 给的内容怎么处理

DeepSeek、Perplexity 等外部 AI 给的说法，**一律先记 ❓**，核实之后再改状态。

这个站已经多次遇到外部 AI「结论对、细节错」：地铁外卡的开通日期和覆盖范围、APEC 场馆的站名、从机场出发的票价区间。台账就是为这种情况设的。

## 文件

- `_topic-decisions.md`：选题判断记录（SOP 第 0 步）
- `<文章 slug>.md`：单篇文章的事实台账。第一份示范：`shenzhen-airport-to-city.md`
